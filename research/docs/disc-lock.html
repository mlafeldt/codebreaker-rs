DISC LOCK CB PS2 · V10 · EE R5900

anti-copy boot chain / how it’s meant to work

The key is derived, never stored.

CodeBreaker’s v10 disc is a self-decrypting loader. The real program ships RC4-encrypted over zlib, and the only key that unlocks it is computed at boot from two things a pirate can’t supply at once: the genuine disc and the actual PlayStation 2.

the whole protection, in one line — FUN_01000248
key = stored ⊕ le_sha1( A ‖ le_sha1( const20 ) )
01

Two factors, one key

Boot forks into two independent reads. Neither value is in the file; each is produced live, and the key needs both. One binds to the console, the other to the disc.

factor 1 · console

EE-FPU bit-mixer

Four calls run a 10-round single-precision float mixer on the EE’s COP1 (madd.s/msub.s), keeping the low 3 bits where the R5900 FPU diverges from IEEE. The result is the same on every PS2 — and unreproducible without cycle-exact EE float hardware.

→ A needs an EE-accurate FPU
FUN_010009c0 → 0x1012a88
factor 2 · disc

CDVD read-key RPC

A SIF remote call crosses to the IOP and asks the CD/DVD subsystem for the physical disc key (0x8000059x). Only a genuine, authenticated disc returns the right value; it lives nowhere in the readable filesystem.

→ const20 needs the original disc
FUN_01000150 → 0x1010980
both required
02

The key schedule

The two factors fold together through a chain of three SHA-1 hashes, then XOR against a stored blind. Each step overwrites the same scratch buffer.

H
Hash the disc key
B = le_sha1(const20) — the disc factor, digested.
H
Fold in the console value
C = le_sha1(A ‖ B) — console and disc now entangled in one digest.
⊕
Unblind into the RC4 key
key = stored(0x1010940) ⊕ C. The stored bytes alone (ce67d054…) are a decoy; they’re meaningless until XORed with a correct C.
The quiet twist: this SHA-1 writes its five state words EE-native little-endian, not as the standard big-endian digest. Every hash is byte-swapped per word — so even a perfect guess of both inputs reconstructs the wrong key until you notice the byte order.
03

The gate

With the key in hand the loader unlocks the payload and jumps in. A wrong key never gets a chance to fail loudly — it simply produces garbage that can’t inflate.

1
RC4-decrypt → zlib inflate → jr 0x100000
The body is decrypted in place (FUN_010000e0, len 0xe9754), inflated to 0x100000 (FUN_01000a58), and executed.
▸ valid zlib stream → payload runs ▸ wrong key → garbage, inflate fails
2
In-payload disc-key re-check
Even after boot, the inflated image checks the disc again (jal at 0x115b14 and 0x1142c0). Belt and suspenders.
▸ pass → CodeBreaker continues ▸ fail → halt
04

Why a copy can’t boot

An attacker needs all three at the same time. Missing any one yields a wrong key, and a wrong key yields nothing to run.

WALL 1

No disc key

A plain data copy can’t reproduce the authentication key, so const20 is wrong and C collapses.

WALL 2

No real FPU

Run it off-hardware or on a loose emulator and the EE float mixer gives the wrong A.

WALL 3

No byte order

Even with both inputs, the little-endian SHA-1 state silently derails a naïve offline reconstruction.

05

How this image defeats it

The v10 BOOT.ELF we reversed is a cracked loader around a stock retail payload — the mirror of v9.2, where the payload is patched and the loader is clean. The crack cuts every wire above, so the unpack runs fully offline with no disc and no hardware.

CUT 1
Factor 1 frozen
− A computed from the live EE FPU
+ stub @0x10060f8 writes A = {938ca6bf, e620cc81, 137a84c2, 78ae9796, 889dca10} as immediates
CUT 2
Factor 2 frozen
− sceSifCallRpc fetches the disc key
+ 0x10060f0 = jr ra; nop (RPC stubbed) · stub hardcodes const20 = {1, 0x39956993, 0x55, 0, 0x05bc0000}
CUT 3
Gate 2 skipped
− jal @0x115b14 / @0x1142c0 run the in-payload disc check
+ RAM patcher @0x1006168 pre-clears the flag, branches past both, then jr 0x100000
key collapses to a constant
29f32f09 0c66b07d c5b12c51 695e432e b1d8ea10

With both factors hardcoded, the schedule is static. tools/cbv10_unpack.py derives this key, RC4-decrypts the body and inflates the image — no disc, no PS2. The payload underneath is untouched stock v10, down to an intact RSA signature check.
