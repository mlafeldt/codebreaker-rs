v10 loader / key derivation and bypass

How the loader derives its key.

CodeBreaker’s v10 loader decrypts a zlib-compressed program with RC4. Its key schedule combines an EE arithmetic result and a CDVD read-key reply. The supplied image freezes both inputs, so it can be unpacked offline.

the key schedule — FUN_01000248
key = stored ⊕ le_sha1( A ‖ le_sha1( const20 ) )
01

Two inputs, one key

The schedule combines A, a digest of EE arithmetic output, with const20, a 20-byte read-key reply. The modified image supplies both as constants.

input 1 · EE arithmetic

EE-FPU bit-mixer

Four calls run a 10-round single-precision float mixer on the EE’s COP1 (madd.s/msub.s), keeping the low 3 bits where the R5900 FPU diverges from IEEE. Correct arithmetic results matter; reproducing the unmodified mixer in software has not been checked here.

→ A digest of the mixer output
FUN_010009c0 → 0x1012a88
input 2 · read-key reply

CDVD read-key RPC

A SIF remote call obtains a status word and 16 read-key bytes. The supplied constants match the software-derived reply for SLUS-20202; these bytes are reproducible from that serial.

→ const20 status + 16 read-key bytes
FUN_01000150 → 0x1010980
both required
02

The key schedule

The two inputs fold together through a chain of three SHA-1 hashes, then XOR against a stored blind. Each step overwrites the same scratch buffer.

H
Hash the read-key reply
B = le_sha1(const20) — status and read-key bytes, digested.
H
Combine both digests
C = le_sha1(A ‖ B) — EE arithmetic output and the read-key reply combined.
⊕
Unblind into the RC4 key
key = stored(0x1010940) ⊕ C. The stored bytes alone (ce67d054…) are an XOR mask; the RC4 key also depends on C.
The quiet twist: this SHA-1 writes its five state words EE-native little-endian, not as the standard big-endian digest. Every hash is byte-swapped per word. Using the standard digest byte order here produces a different key.
03

Decrypt, then check

The loader decrypts and inflates its body, then transfers control to the payload. The payload’s later startup checks are separate from decryption.

1
RC4-decrypt → zlib inflate → jr 0x100000
The body is decrypted in place (FUN_010000e0, len 0xe9754), inflated to 0x100000 (FUN_01000a58), then entered by the loader.
▸ derived key → recovered program ▸ wrong key can prevent inflation
2
Payload startup checks
The call at 0x115b14 checks the decoded read-key serial against SLUS-20202. Another call at 0x115b30 checks a byte of an RPC result. The call at 0x1142c0 sends function 4 to server 0xfa6a007e; its server-side role remains unresolved.
▸ serial and result checks located ▸ mismatch → error flags
04

What the evidence establishes

Offline unpacking and the inspected instructions support the key reconstruction. They do not establish physical disc authentication or the final outcome of every startup check.

READ-KEY

Reproducible reply

The 20 bytes match status 1 plus serial-derived read-key bytes. This concrete input is reproducible in software.

EE ARITHMETIC

Result accuracy

The unmodified mixer has not been independently reproduced here. Correct arithmetic results matter; cycle accuracy has not been shown necessary.

SCOPE

Bounded evidence

Intact inspected instructions do not authenticate the whole payload. The immediate failure handler marks flags; its final boot-failure path was not traced.

The serial reconstruction uses PCSX2’s cdvdReadKey implementation at a pinned revision. It matches the hardcoded reply exactly; a complete boot on hardware or PCSX2 was not run.
05

How this image bypasses the inputs

The supplied v10 BOOT.ELF has a hardcoded-input stub and a RAM patcher. These changes make its key schedule static and bypass the startup calls below. An intact inspected signature verdict does not establish that the whole payload is untouched retail firmware.

With both inputs hardcoded, the schedule is static. tools/cbv10_unpack.py derives this key, RC4-decrypts the body and inflates the image offline. The inspected RSA verdict consumes its comparison result; signature-scheme security and whole-image authenticity were not established.
